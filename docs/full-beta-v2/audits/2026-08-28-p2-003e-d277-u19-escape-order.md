## 1. The three candidate causes, discriminated by measurement

D-276 named three candidate causes to distinguish. 003E measured each.

### (A) intrinsic pad / footprint / board-edge escape geometry — **REFUTED**

U19 is an SOT-23-8 at the far west board edge (west row x = 1.558, east row
x = 3.833; board west edge x = 0.000, EDGE_CLR = 0.5 mm). U19.3 (N_POL) is the
**middle west-row pin** at (1.558, 27.930), a 1.325 × 0.500 mm pad flanked by
U19.2 (REF_POL, north, y = 28.580) and U19.4 (GND, south, y = 27.280) at
0.65 mm pitch, walled to the west by the board edge and to the east by the
opposite pin row (U19.6 N_BATDIV at (3.833, 27.930)).

Measured on the **authoritative board** (0 signal tracks; U19 is **not** moved
by the c3 placement — c3_00 moves only R75/U18/R79), `qb.escape(U19.3, 'B',
w, w, …)` returns a **legal ≥ 0.150 mm escape** (also at 0.200 and 0.250 mm),
launching **east** into the inter-row gap. Its sibling U19.2 also escapes.
Both are **single-lane** (freedom 1, east only); the two end pins U19.1/U19.4
have 4 ways, the east-row middles 2. So the pad **can** leave its own copper —
intrinsic geometry is not the blocker.

### (B) route-order / already-laid copper — **CONFIRMED (the cause)**

The blocker histogram named **only** board_edge and U19's own pins — never a
foreign net's track — which already points away from far-away laid copper.
U19 (y ≈ 28) is geographically isolated from the western-BPP-trunk congestion
(y 60–93) of D-270…D-275, so the contention is **local to U19's pin field**.

Isolated on the empty authoritative board, routing the two contending
connections in the two possible orders is decisive:

| order | first connection | then sibling freedom | second connection |
|---|---|---|---|
| **driver (U19.2 first)** | REF_POL TP24.1→U19.2 **ok** (8.610 mm) | U19.3 → **0 ways** | N_POL TP23.1→U19.3 **NO_LEGAL_ESCAPE** |
| **swapped (U19.3 first)** | N_POL TP23.1→U19.3 **ok** (6.118 mm) | U19.2 → **1 way** | REF_POL TP24.1→U19.2 **ok** (13.372 mm) |

The driver-order row **reproduces D-276 byte-exact** — the same fail string and
the same blocker signature (`board_edge ×21, U19.4 ×17, U19.2 ×13, …`). The
swapped row **routes both**. So the escape is denied purely by the order, and
the order is **asymmetric**: U19.2 first kills U19.3, but U19.3 first does not
kill U19.2.

**Why asymmetric (the geometry).** U19.2 sits **north** of U19.3, but its target
TP24.1 (6.0, 22.5) is **south**; so U19.2's route escapes east into the inter-row
gap and then crosses **south through the gap**, over U19.3's only (east) lane,
sealing it. U19.3's target TP23.1 (6.0, 25.25) does **not** lie across U19.2, so
U19.3-first takes its lane and U19.2 detours around the laid copper. This is a
textbook planar-fanout ordering: among boxed pins all exiting the same way, the
one whose route crosses a sibling must go **last**.

### (C) minimum placement ECO — **NOT REQUIRED**

Because (B) is fixable by order alone (both route in the swapped order), no
placement displacement/orientation search was needed or run. Cause (C) is left
un-exercised, as the required investigation order specifies (C only if A and B
are exhausted).

## 2. The fix — a measured planar tie-break, cardinality-0

The scheduler `order_tight` already routes the tightest pin first, re-measured
before every fine-pitch pin (PR-19/23/30/32/38). U19.2 and U19.3 **tie on every
existing key**: slack +0.14 mm, ways-out 1, width — so the order fell through to
the queue's arbitrary MST order, which put U19.2 first (the backwards choice).

The repair adds **one final tie-break** on live geometry: among rows tied on
`(slack, ways-out)` with **ways-out ≤ 1** (the boxed-single-lane class), the pin
whose **pad→target span contains a tied sibling's pad** must cross that sibling,
so it is ordered **last**. Concretely, `crossings[i]` counts tied siblings whose
pad falls inside row *i*'s pad→target bounding span, and the sort key becomes
`(slack, ways-out, width, crossings)`. For U19: U19.2's span contains U19.3
(crossing 1), U19.3's span does not contain U19.2 (crossing 0) → **U19.3 routes
first**, and both escape.

**Scope / blast radius.** The term is **0 for every pin with a second way out**
(guarded by `fr_a ≤ 1`) and is the **last** sort key, so it only settles an
**exact** `(slack, ways-out, width)` tie that today resolves arbitrarily — it can
never reorder across tightness classes. The only two `tight` groups are `U18`
(pinned to a fixed schedule via `AQROOT_U18_ORDER`, so `order_tight` never
processes it) and `U19` (this block). The west-margin prefix routes identically
(verified: the pre-U19 log is unchanged). No copper is laid by the tie-break —
it is a pure read-only geometry measurement, consistent with the rest of
`order_tight`.
