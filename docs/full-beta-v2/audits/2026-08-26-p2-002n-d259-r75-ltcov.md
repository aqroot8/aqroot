```

/ PP 7628 0.2028 / In3.Cu 0.0152 / core 0.4000 / In4.Cu 0.0152
/ PP 7628 0.2104 / B.Cu 0.0350

Listed materials total **1.5544 mm**, or **1.5744 mm** with both solder masks.
**That is not a discrepancy.** The board is a **nominal 1.6 mm construction**;

earlier derived split is not retained merely because it added up more neatly.

The outer dielectric — **0.2104 mm of 7628 to the adjacent reference on both
sides** — is the one figure carried from JLC04161H-7628, and it is what keeps
the outer-layer routing plans structurally valid.

## 4. R75 — and the measurement that says translation was never going to work

**The Kelvin mismatch is pinned by geometry unless the shunt can turn.**
`U18.8` and `U18.9` sit at the **same y** (70.300), 0.5 mm apart in x. R75 is a
**5.925 mm** shunt whose pads lie along y. For any pure north/south translation

nearly the shunt's own length**. Measured over a ±8 mm box at 0.5 mm in all four
rotations:

```

reached the Kelvin test: 28 poses, ALL rot 90/270

**every rot 0/180 pose is blocked by the R80/R81/R82 courtyards at x 7.30**. So
the part costing the Kelvin specification is the divider column, not R75.

§6 pins Q2, Q3, D9, U18, U14 and the FET placement; it does **not** pin

## 7. A harness change made, measured, and deliberately REVERTED

`BAT_MAIN routed clearance` is a rule about the net and fires on either side of
the pair, so a control track passing a BAT_MAIN **pad** appears to owe it
0.300 mm exactly as it owes a BAT_MAIN track 0.300 mm. The router's `margin()`
returned `clr_pad` (0.200 mm) for every pad regardless of net, which is why DRC
kept reporting actuals — 0.2371, 0.2500, 0.2750, 0.2778 mm — that all sit
between the two figures. Raising wide-net pads to 0.300 mm looked like the fix.

**It is not, and the board said so within one screen.** With the bump in force,
`U18.8` and `U18.9` — the two D-249-ruled Kelvin taps that must leave an MSOP-10
pin field straight past R75's own pads — both came back `NO_LEGAL_ESCAPE`. Those
taps route legally today at **0.150 mm** under the pad-escape necking block, a
later and more specific rule than the class clearance, so DRC does **not** in
fact demand 0.300 mm there.

A router-side margin cannot see which corridor rule governs a given pair, so it
would have to over-apply — and **over-applying a clearance is how a legal escape
becomes NO_LEGAL_ESCAPE.** The change was reverted and the reasoning left in the
code so it is not re-attempted. The per-connection DRC gate remains the
authority: a route that genuinely violates 0.300 mm beside a wide-net pad is
rejected there, by name.

This is the third time in three tasks that a well-intentioned blanket rule
change has been narrower in the rules than it looked in the code. **A relaxation
applied where nothing needed relaxing is a restriction; so is a restriction
applied where the rules already made an exception.**
