## 1. The three candidate causes, discriminated by measurement

### (A) intrinsic pad / footprint / board-edge geometry — **REFUTED**

escape lane (east, into the field). On the empty authoritative board it still

### (B) route-order / co-located landing barrel — **CONFIRMED, and it is a CO-LOCATION, not a corridor**

Two `N_BATDIV` connections are co-terminal at U19.6's single east escape — the
local `U19.6→R89.2` escape and the 46 mm cross-board `C61.1→U19.6` bypass hop —
so both want a THROUGH-via barrel at that one lane. On the committed 003G BASE
board the two barrels land **0.450 mm centre-to-centre**, i.e. two 0.20 mm drills
at exactly the **0.25 mm `min_hole_to_hole` floor, ZERO margin**
(`u19_escape_probe_003h.py` §A: `c2c=0.450 mm edge=0.2500 mm`). The 003G field
perturbation is what tipped `C61.1`'s landing off that zero-margin fit onto the
co-located point (measured: 0.035 mm from the `U19.6→R89.2` via, **hole edge
−0.165 mm**), and DRC answered `holes_co_located` / `hole_to_hole` on every pass.

**The defect (measured).** `connect_hop` places a hop's escape via by a fast path,
`free_everywhere`, that tested only **COPPER clearance** — which `point_free`
WAIVES for the via's own net — and NOT hole-to-hole. `via_site`, the fallback
placement, DOES enforce hole-to-hole (`hole_clr=250000`), but it is only consulted
when `free_everywhere` fails. So a hop whose single-lane pad escapes straight onto
a co-terminal **SAME-NET** barrel dropped a second drill on top of the first: the
own-net copper waiver let the co-located site look "free", and the net-agnostic
drill-spacing was never checked at that site.

barrel (as `U19.6→R89.2` does) and route `C61.1→U19.6`:

## 2. The fix — D-280, a NET-AGNOSTIC HOLE-TO-HOLE GUARD in `free_everywhere`

`qrouter.connect_hop`'s `free_everywhere(x, y)` now, in addition to the existing
all-layers `point_free` copper check, enforces the net-agnostic `min_hole_to_hole`
floor for the barrel it is about to drill:

```python
h2h = 250000 if os.environ.get('AQROOT_D280') else 0
...
if h2h:
    for hole in qb.holes:
        if math.hypot(hole.cx - x, hole.cy - y) < \
                max(hole.hx, hole.hy) + via_drill / 2.0 + h2h:
            return False
return True
```

A co-locating site is rejected and the placement falls through to `via_site`,
which finds the nearest reachable barrel that clears the floor — the base's own
0.45 mm landing. The guard **ADDS a rejection only**: it relaxes nothing, moves no
part, invents no via, and can only relocate a co-locating via to a legal,
separated site.

**Single-sourcing / DRU alignment.** The `250000` (0.25 mm) is the governing DRU
`min_hole_to_hole` from `aqroot-Beta-v2.kicad_pro` (verified `"min_hole_to_hole":
0.25`), and it is byte-identical in structure to the two existing enforcements of
the same floor in `qrouter.py`: `via_site(... hole_clr=250000)` and the POFV path
`max(h.hx, h.hy) + via_drill / 2.0 + 250000`. The guard uses the SAME literal and
the SAME `max(hole radius) + via_drill/2 + floor` formula as POFV — it is safely
aligned with the governing DRU and the existing `via_site`/POFV constants, not a
new or looser value. (No named module constant was introduced: the repo precedent
is the inline `250000` literal in `via_site`/POFV, and refactoring those
out-of-scope lines during a closeout would enlarge the blast radius for no gain.)

**Env-gate.** `AQROOT_D280` unset ⇒ `h2h = 0` ⇒ the guard is inert and the
pre-003H behaviour reproduces byte-for-byte, so every earlier measurement, the
whole `router_regression` G1–G11 set, and the bridge / u19 gate sets stand
untouched. Env-gating is the same precedent used by D-277/D-278/D-279.

**Blast radius.** The guard fires only inside `connect_hop`'s direct-escape via
placement, only when `AQROOT_D280` is set, and only to REJECT a barrel site that
violates the manufacturing drill-spacing floor. It cannot make a previously legal
placement fail (a legal site already clears the floor); it can only redirect a
co-locating placement to a separated one, or — if every candidate co-located —
fall through to the untouched B.Cu ladder. On the full run no route was lost to
over-rejection (every 003G route is retained and C61.1 is gained).
