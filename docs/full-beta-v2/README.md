# AQROOT Full Beta v2 Engineering Record

**Purpose:** this directory is the authoritative engineering record for AQROOT
Full Beta v2. It exists so that the reasoning behind the design — not only its
output files — is preserved in the repository, in Git history, and on GitHub.

Everything here is text. Nothing here is a design file. Nothing here is
generated by a tool. If a fact matters and is not recorded in this directory or
in the KiCad sources, it is not part of the engineering record.

---

## What each baseline is

| baseline | location | role |
|---|---|---|
| **Beta-DM** | `hardware/beta-dm/` | The **validated implementation / manufacturing baseline.** Design-side complete, DRC 0 errors, fabrication package generated. Full Beta v2 inherits its implementation knowledge, its resolved MPNs and its proven blocks. |
| **Frozen Full Beta** | `hardware/beta/`, tag `beta-full-reference-v1` | The **feature / reference architecture baseline.** It records what the full feature set looks like. It is **not** fabrication-ready and was never fully validated (281 unconnected items and 58 ERC violations at freeze). |
| **Full Beta v2** | not yet created | The **active feature-complete showcase design.** Derived from Beta-DM, reintroducing the missing Full-Beta features in a controlled, gated way. |

### Preservation rules

- `hardware/beta-dm/` **must remain preserved** unless a CTO gate explicitly
  authorizes a change to it. It is the fallback that lets the programme
  fabricate something real if Full Beta v2 stalls.
- `hardware/beta/` and the tag `beta-full-reference-v1` are **historical
  references** and are read-only. Every Full Beta v2 commit must be able to
  prove `git diff beta-full-reference-v1 -- hardware/beta/` is empty.
- Design files may only be changed **after the relevant CTO gate authorizes
  them.** The gate list lives in [PROGRESS.md](PROGRESS.md).

## How to read this record

- **`transcripts/` is append-only.** A transcript is a historical record of what
  was asked and what was answered at a point in time. Transcripts are never
  edited, corrected or deleted. A transcript can become *outdated*; it can never
  become *wrong*, because it is a record of what was said, not of what is true
  now.
- **`CTO_DECISIONS.md` is the current source of truth.** When an older
  transcript or audit conflicts with a later CTO ruling, **the CTO decision
  wins.** Do not re-derive current direction by reading old transcripts.
- **`audits/` are dated snapshots.** An audit is true as of its stated
  repository HEAD. It is superseded by later audits, never rewritten.
- **`CHANGELOG.md` records what changed and why**, in chronological order.
- **`PROGRESS.md` records where we are** — gate status, percentages, blockers.

Order of precedence when two documents disagree:

```
CTO_DECISIONS.md  >  latest audit  >  ARCHITECTURE.md  >  older audits  >  transcripts
```

## Conventions

- **Dates are absolute.** Never "last week", never "recently".
- **Every claim is sourced.** Measured from the board, quoted from a document,
  or explicitly marked as requiring verification. "Measured" and "assumed" are
  never blurred.
- **Task IDs** use the form `FBV2-<AREA>-<NNN>` (for example `FBV2-DOC-001`).
- **Gate IDs** use the form `FBV2-<PHASE><N>` (for example `FBV2-A2`).
- A verbatim record that cannot be recovered is marked
  `> [VERBATIM SOURCE UNAVAILABLE — DO NOT RECONSTRUCT FROM MEMORY]`
  and is never reconstructed from memory.
