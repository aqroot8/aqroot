## 1. D-269(a) — clearance is the fourth and last property

> **BAT_MAIN 0.300 mm routed clearance is a CURRENT-PATH-ROLE requirement, not
> an entire-net-name requirement. The high-current BPP trunk remains B.Cu outer
> 1 oz and zero-via. The western cut is addressed by the minimum necessary
> low-current control-layer offload, not further placement changes.**

D-249 ruled **width** by path role, D-264 ruled **layer**, D-267 ruled **via
geometry**. Each was the same defect one property over: a rule written for 1.5 A
of pack current applied to a branch carrying nanoamps because it shares a net
name. `BAT_RAW R77.1 → R79.1` — two 0.20 mm divider taps held 0.300 mm apart —
is the clearance case.

In force as `path_role_dru.main_clearance_rules()`:

```
(rule "BAT_MAIN routed clearance - current path role - D-269"
	(constraint clearance (min 0.30mm))
	(condition "A.hasNetclass('BAT_MAIN') && A.Type != 'Pad' && B.Type != 'Pad'
	            && !A.enclosedByArea('BAT_RAW_DIVIDER_TAP_0') && … _1 && _2 && _3"))
```

**The 0.300 mm requirement is untouched on every current-carrying role.** The
exclusion reaches four bounded corridors grown from the divider chain's own
copper, and inside them the **existing** board rules govern — the board default
of **0.200 mm**. *No new clearance number was invented anywhere.*

**One corridor per branch, not one for the chain.** `enclosedByArea` honours only
the **first outline** of a multi-outline rule area — the fact D-266 learned and
this task re-learned twice — and the four divider links are far apart, so a
single shared area silently stopped covering whichever branch was not in its
first outline. Every other D-249 corridor on this board is per-branch for the
same reason.

**A bounded TAP corridor also has to carry its width allowance.** Before D-269
the divider rows had no area, so each got an anonymous `BAT_STUB` corridor
carrying the width it used. Naming the corridor for the *clearance* exclusion
took that away and the same copper returned as `track_width (rule 'BAT_MAIN
minimum width' min 0.6000 mm)` — a relaxation applied where nothing needed
relaxing, exactly the lesson PR-48 recorded. The corridor now registers the
narrowest width its own copper uses.

## 6. Why it changed, and it is this task's own doing

On the pre-D-269 board (002V), removing all control copper *did* restore
1.50 mm. On this board it does not. The difference is the copper D-269 made
routable:

| removed from B.Cu | `R75.2 → D9.1` |
|---|---|
| nothing | 0.60 mm only (54.2 mm) |
| `BAT_RAW` alone | 0.60 mm only (29.3 mm) |
| all seven control nets | 0.60 mm only (57.8 mm) |
| `BAT_RAW` + `LTC_OV` | 0.60 mm only (20.4 mm) |
| **all seven control nets + `BAT_RAW`** | **1.50 mm, 19.9 mm** |

**`R80.1 → Q2.7` at 0.50 mm × 29.022 mm and `D12.1 → R77.1` at 0.60 mm ×
14.637 mm are now in the margin**, and they are microamp *TAP* copper on a
power-named net. §9 excluded "power/current nets" from the offload candidate set
**by net class**, and by net class that is right — but by **path role** these two
runs are exactly the kind of low-current copper §13 would have been willing to
move. The candidate list and the ruling it serves are scoped differently.

That is the honest statement of the trade: **closing `BAT_RAW` — which §7
required, and which D-269 achieved — consumed part of the corridor the trunk
needs.** Both results are real; neither cancels the other.

## 7. Section 25 — DECISION STOP

No control-offload set opens ≥1.20 mm, so the task stops here as instructed.
Not done, per §25: no further component moved, no In2/In3 trunk, no high-current
via, and **the 45.467 mm long route was not accepted by default**.

**The one set that works is "all seven control nets AND `BAT_RAW`"** — which is
not an offload but "put nothing on B.Cu in the western margin", and it delivers
the **19.9 mm** trunk at 1.50 mm, i.e. essentially the clean-board route.

## 8. Decision required

1. **Extend the offload candidate set from net class to path role.** The two
   `BAT_RAW` divider runs in the margin carry microamps. D-269 has just
   established that clearance follows path role; §9's candidate list is the last
   place that still reasons by net class. Whether `R80.1 → Q2.7` and
   `D12.1 → R77.1` may take a layer excursion is a CTO call — **note §6 of this
   task's own brief forbids a `BAT_RAW` In2/In3 exception**, so this needs an
   explicit new ruling, not an inference.
2. **Or accept that the western margin cannot host both the control field and a
   ≥1.20 mm trunk**, and choose between the F.Cu via-array bridge and the
   reservation-dependent long B.Cu route (2.29× resistance, quantified in the
   D-267 audit) as §25 anticipates.
3. **`BAT_RAW`'s closure should not be given back.** It took four rulings to get
   there and it is the first time the divider chain has ever been one island.
